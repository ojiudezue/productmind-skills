# Viability Criteria

Score each dimension as **Strong**, **Moderate**, or **Weak**. If 3+ dimensions are Weak, flag the project.

## 1. Problem Clarity & Urgency

- **Strong**: Specific, well-defined problem that people actively try to solve today
- **Moderate**: Real problem but fuzzy edges or low urgency
- **Weak**: Solution looking for a problem, or "nice to have" only

## 2. Target User Definition

- **Strong**: Can name the person, their role, their context, and why they'd care
- **Moderate**: General audience defined but no sharp persona
- **Weak**: "Everyone" or "developers" with no further specificity

## 3. Competitive Landscape

- **Strong**: Competitors exist (validates market) but have clear gaps
- **Moderate**: Crowded space but a plausible angle exists
- **Weak**: Either no competitors (unvalidated market) or dominant incumbents with no visible gap

## 4. Differentiation

- **Strong**: Clear, defensible advantage — technical, distribution, insight, or data
- **Moderate**: Differentiation exists but is easily copied
- **Weak**: "We'll just do it better" with no structural advantage

## 5. Technical Feasibility

- **Strong**: Builder has the skills, the stack is known, no major unknowns
- **Moderate**: Some unknowns but researchable; may need to learn a new tool
- **Weak**: Requires breakthroughs, unavailable APIs, or skills far outside current capability

## 6. Revenue or Impact Path

- **Strong**: Clear monetization model or measurable impact metric from day one
- **Moderate**: Plausible path but requires scale or experimentation to validate
- **Weak**: No idea how this makes money or creates measurable value

## Decision Matrix

| Weak Scores | Recommendation |
|---|---|
| 0-1 | Proceed with confidence |
| 2 | Proceed with eyes open — document the risks |
| 3+ | **Pause.** Recommend pivot, deeper research, or conscious risk acceptance before any code. |

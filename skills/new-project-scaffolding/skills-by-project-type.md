# Skills by Project Type

When scaffolding, recommend and fetch skills across ALL four categories — not just one.

## Category: Design

| Skill | When to fetch |
|---|---|
| UI design / component patterns | Any project with a visual interface |
| Interaction design | Apps with complex user flows (multi-step, drag-drop, real-time) |
| Information architecture | Products with navigation, search, or content hierarchy |
| Accessibility (a11y) | All UI projects — not optional |
| Responsive / adaptive layout | Web apps, PWAs |

## Category: Testing

| Skill | When to fetch |
|---|---|
| Unit testing (language-specific) | Always |
| Integration testing | Any project with external dependencies (DB, API, services) |
| E2E / UI testing | Any project with a user interface |
| Performance / load testing | APIs, real-time apps, data-heavy apps |
| Security testing | Apps handling auth, payments, PII |

## Category: Product

| Skill | When to fetch |
|---|---|
| Product strategy | Always — feeds the product brief |
| Analytics instrumentation | Any shipped product (define events early) |
| User research methods | Products targeting real users |
| Prioritization frameworks | Projects with ambiguous scope |

## Category: Platform-Specific

| Skill | When to fetch |
|---|---|
| iOS (Swift/SwiftUI) | iOS apps |
| Android (Kotlin/Compose) | Android apps |
| Web (React/Next/Svelte) | Web apps |
| API design (REST/GraphQL) | Backend services |
| CLI design | Command-line tools |
| Database design | Projects with persistent data |
| Infrastructure / DevOps | Projects needing deployment beyond a simple host |

## How to Apply

1. List all applicable skills from the table above
2. Check which are available in the current environment
3. For available skills, apply them during the relevant scaffold step
4. For unavailable skills, list them as gaps in `docs/milestones/m0-scaffold.md`
